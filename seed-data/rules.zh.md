# Todo 整理规则

## 用途

FocusDock 的 Todo 窗口是一块简洁提醒区域，不是笔记本，也不是邮件摘要。`todo.md` 只应该包含真实行动、已确认会参加的活动、有日期或截止时间的事项，以及需要用户主动确认的短行动项。

不要把完整邮件正文、活动背景、链接解释或推广文案放进 Todo。背景信息放在每日早报或私有日志里。

## Todo 写法

任务要短，一眼能看懂。

推荐格式：

`项目：行动/关键词 @YYYY-MM-DD`

示例：

- `BIA：Welcome Night 5-8 @2026-08-24`
- `BCSSA：Boba Run @2026-08-27`
- `RecWell：签 Waiver`

`todo.md` 可以使用英文标题 `Inbox`、`Todo`、`Done`，也可以使用中文标题 `收件箱`、`待办`、`完成`。FocusDock 能同时解析两种标题。

- `待办` / `Todo`：有明确日期、明确行动和明确承诺的事项。
- `收件箱` / `Inbox`：仍不确定、缺少日期，或需要确认的信息。
- `完成` / `Done`：已完成任务。

不要因为任务完成就直接删除。应先移动到完成区。

## 每日早报

每日早报应该帮助用户在约 30 秒内理解今天和近期最重要的事项。

支持的分区：

- `## 今天` / `## Today`
- `## 临近截止` / `## Approaching Deadlines`
- `## 需要确认` / `## Needs Confirmation`
- `## 可选活动` / `## Optional Events`
- `## 垃圾/忽略` / `## Trash / Ignore`
- `## 可加入 Todo 候选` / `## Todo Candidates`

普通分区使用编号列表。Todo 候选必须编号，并把短 Todo 包在反引号里。

## 候选项规则

Todo 候选优先级从高到低：

1. 用户已经注册、预约、提交、购买或确认的事项。
2. 必做或半必做的学校事项，例如表格、账单、培训和官方预约。
3. 会影响日程安排的近期选择。
4. 近期发生的高价值可选活动。
5. 与用户当前身份或处境高度相关的资源。
6. 普通推广、泛泛的职位推荐和低价值简报。

如果某个事项已经在 `todo.md` 中，每日早报可以提醒它，但不应该再次放进 Todo 候选。

保持 Todo 干净，让每日早报承载背景信息。
